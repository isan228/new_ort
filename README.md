# ОРТ 2026

Платный тренажёр ОРТ для школьников Кыргызстана: банки вопросов, конструктор теста по темам и навыкам, связанные вопросы (чтение), flashcards, история, глоссарий, админка и TXT-загрузки.

Стек: **Node.js + Express + Sequelize + PostgreSQL** и **React (Vite)**. Без Docker. API сразу пригодно для будущего мобильного клиента.

## Как устроено (USMLE → ОРТ)

| Было (USMLE) | Стало (ОРТ) |
|---|---|
| Step 1 / 2 / 3 | `trackGroup`: `main` / `state_lang` / `subject` |
| Subject × System теги | Тема × Навык (`topic` / `skill`) |
| `usmleSubscriptionEndDate` | `subscriptionEndDate` |
| `/api/tests/usmle/*` | `/api/tests/ort/*` |
| MedicalImage | TermImage (школьные термины) |
| `universityId` | нет — продукт только про ОРТ |

Подписка одна на весь раздел. Контент не привязан к вузу.

Треки:

1. **Основной тест** — математика, аналогии, чтение, грамматика.
2. **Государственный язык** — обязательный кыргызский.
3. **Предметные** — химия, биология, физика, математика, история, английский и др.

## Симуляция ОРТ

Отдельный банк вопросов (`bank = 'simulation'` у `Subject` и `Test`): вопросы симуляции не попадают в конструктор, случайный основной тест, чтение и статистику — и наоборот.

- Иерархия: тест симуляции (основной рус/кыр, предметы, госязык) → вариант №N → блок (таймер) → часть (число вопросов, формат) → тема из справочника теста (необязательно).
- Новый вариант заполняется по официальной структуре ЦООМО 2026 (`server/utils/simCatalog.js`), всё редактируется в админке `/админ/sim`.
- Публикация проверяет заполненность и сохраняет снимок (`SimVersion`): ученики проходят снимок, правки после публикации не меняют сохранённые результаты.
- Таймер блока считает сервер: время старта хранится в `SimAttempt`, просроченный блок закрывается при следующем запросе, вернуться в закрытый блок нельзя.
- Редактор (`/redact/sim`) видит структуру и загружает вопросы в части и темы теми же TXT/формами, что и в «Программе ОРТ».

## Конструктор «Создать тест»

- Темы — разделы и подразделы «Программы ОРТ» (практический банк). Ученик отмечает предметы и темы, вводит одно число вопросов, выбирает сложность («Смешанные» или ровно один уровень 1–4) и фильтры «Все / Нерешённые / Неправильные / Правильные / Помеченные».
- Вопросы делятся между темами поровну, остаток получают случайные темы, дефицит одной темы добирается из других (`server/utils/practice.js`). Если подходящих вопросов меньше нужного — тест не создаётся, ученик видит сообщение.
- Тренировка хранится на сервере (`PracticeSession`, `PracticeAnswer`): ответы, таймер и незавершённые тесты переживают перезагрузку. По 00:00 сервер сам закрывает тест.
- Статус вопроса — по последнему ответу (пропуск не считается ответом). Красный флажок — `QuestionFlag`, хранится в аккаунте.
- Сложность вопроса — поле `"Difficulty":"1".."5"` в TXT или звёзды в форме вопроса; без неё вопрос попадает только в «Смешанные».

## Student Bot (Telegram)

Бот подбирает исполнителя для разрешённой студенческой задачи по дате, паре и месту (ТЗ релиз 2.5). Работает в том же процессе и той же базе, что и сайт; таблицы `Sb*`.

- Один аккаунт, два режима: «Не могу присутствовать» (заявка) и «Могу присутствовать» (свободные слоты). Подбор двусторонний: пол, факультет, место, слот покрывает всё время заявки, занятость обоих.
- Приглашения: 15 минут, 5 минут если старт меньше чем через час; не больше 3 ожидающих. Принятие атомарное под блокировкой строк — второго подтверждения быть не может.
- Переписка идёт через бота (текст, фото, документы до 20 МБ), контакты — только по действию участника. Через 48 ч после закрытия заказа текст удаляется, если нет открытой жалобы.
- Завершение — подтверждение от обоих, затем раздельные оценки по ролям; средний рейтинг открывается после обеих оценок или через 48 ч.
- Отмены: 3 минуты после принятия — без последствий; 3 односторонние за 24 ч — пауза 12 ч; 5 за 7 дней или 4 поздние — до проверки администратором. Взаимная отмена без штрафов.
- Доступ: 72 ч бесплатно всем от `LAUNCH_AT`, затем тарифы 7/30 дней. После первой оплаты — авансовые сутки, вычитаются из следующей оплаты. Рефералы: +3/+3 после оплаты обоих, не больше 30 бонусных дней за 30 суток. Оплата — через Finik сайта: бот присылает ссылку и скриншот QR (`studentbot/payments.js`, `qrShot.js`), вебхук сайта продлевает доступ; администратор может отметить оплату и вручную.
- `/admin` в боте — только для `SB_ADMIN_IDS`: пользователи, заказы, обращения, доступ и тарифы, статистика, справочники. Каждое действие с причиной пишется в журнал `SbModeration`.

Код: `server/studentbot/` (`deals.js` — сделки, `access.js` — доступ, `scheduler.js` — сроки и напоминания, `screens/` — экраны, `admin.js`). Вебхук `POST /api/telegram/webhook` с секретным заголовком. Настройка — раздел 10 в [DEPLOY.md](DEPLOY.md).

## Запуск локально

1. Установите PostgreSQL (служба должна быть запущена).

2. Поставьте зависимости и дайте скрипту самому создать базу, таблицы и сиды:

```bash
npm install
npm run install:all
npm run setup:db
```

Если пароль суперпользователя не `postgres` (PowerShell):

```bash
$env:POSTGRES_PASSWORD="твой_пароль"; npm run setup:db
```

Скрипт при отсутствии скопирует `.env` из `.env.example`, создаст пользователя и базу из `DATABASE_URL`, накатит схему и демо.

3. Запуск:

```bash
npm run dev
```

- API: http://localhost:4000  
- Сайт: http://localhost:5173  

При старте сервер сам синхронизирует схему, посеет теги, тарифы, админа, демо-ученика и демо-банки.

Демо-логины:

- ученик с подпиской: логин `demo`, пароль `demo123` (страница `/login`)
- админ: логин `admin`, пароль `admin123` — только по служебной ссылке `/админ` (в меню сайта её нет)

Оплата — **Finik** на `ort.kg`. В `.env` только `FINIK_API_KEY` и `FINIK_ACCOUNT_ID`. Ключи RSA — `finik_private.pem` и `finik_public.pem` в корне репозитория. Вебхук: `https://ort.kg/api/payments/webhook`. Без ключей локально остаётся демо-оплата.

Поле файла: **`pdf`** (или `file`).

Вопросы:

```
"ID":"101"
"Q":"Текст"
"A1":"вариант"
"A2":"вариант"
"A3":"вариант"
"A4":"вариант"
"Correct":"2"
"E":"Объяснение"
"Topic":"Алгебра"
"Skill":"Вычисление"
```

Связанные (один `GroupID` = один текст):

```
"GroupID":"1"
"ID":"201"
"Q":"..."
```

Карточки:

```
=== Проценты и доли ===
"ID":"1"
"Front":"Чтобы найти p% от a, нужно ______"
"Back":"a × p / 100"
```

Примеры лежат в `server/data/`.
